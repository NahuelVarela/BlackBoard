## 1. Slice breakdown

### #1/core — Core tuple log (JSONL append + schema)
- `Tuple { id, type, state, actor, summary, ts, refs }` in `src/tuple.rs` with serde.
- `type`: `slice-state` | `issue-opened`. `state`: `open|planning|executing|done|blocked` (+ `open` only via sync; agents assert others — enforced in `store::append` with `allow_open: bool` flag).
- Validation: `done` requires non-empty `summary`; `blocked` requires `summary` (reason + unblock); `id` format `#<n>/<slice>` or `#<n>` for issue-opened.
- `current_state(tuples)`: max `ts` (RFC3339, chrono DateTime<Utc>), tiebreak `actor` lexicographic. Pure fn, unit-tested.
- `store::append(tuple)`: mkdir `.blackboard/`, append one JSON line to `log.jsonl`, upsert indexer row. Atomic append (single write + fsync). Never edit history.
- Tests: invalid done-without-summary rejected; reduction tiebreak deterministic; append creates files.

### #1/cli — CLI verbs with `clap`
Verbs (exact):
- `bb init` — create `.blackboard/{log.jsonl,index.db}` if missing. Idempotent.
- `bb pick #1/<slice> --by <actor>` — assert `planning` (reject if already `done`? allow re-plan unless done; reject double-done).
- `bb state #1/<slice> <planning|executing|blocked> --by <actor> --summary "..."` — generic transition (heartbeat).
- `bb done #1/<slice> --by <actor> --summary "<=2 sentences>"` — assert `done` = tick.
- `bb show #1 [--explain]` — slices + refs, ~200 tokens, <=40 lines. `--explain` prints `read: <index.db> (no git)` proof line + row count.
- `bb board [--explain]` — all problems ticks view (section per `#n`).
- `bb sync <md-path> [--offline]` — see #1/sync. `--offline` skips `gh`, uses `GH_MOCK` for tests.
- Global: `--repo <path>` (default cwd) for tests; all reads hit `index.db` only (assert via `--explain`, no `git` subprocess anywhere in `src/` — grep-enforced).
- Commit-msg helper: `bb show` prints `refs: ... | gh#<n>` so agents copy into `Refs #<n>`.

### #1/board — Local indexer + board views (no git reads)
- `rusqlite` `bundled`: table `current(id TEXT PRIMARY KEY, type TEXT, state TEXT, actor TEXT, summary TEXT, ts TEXT, refs JSON)`.
- `rebuild()`: truncate + replay `log.jsonl` (used on init/open if db missing; also recovery path).
- Every read (`show`/`board`) opens `index.db` read-only. Never shells to `git log/show`. Prove: `rg -n "Command.*git" src/` empty + `--explain` output.
- Rendering (`src/board.rs`): legend `[ ] open, [.] planning, [~] executing, [x] done, [!] blocked`; per-problem block exactly like spec §Slices example; `refs:` line from latest `issue-opened` tuple.
- Tests: append 5 opens -> board shows 5x `[ ] open`; transition core->executing -> `[~]`; indexer survives delete+rebuild.

### #1/tui — TUI board (`ratatui`, same projection, watch mode)
- `bb tui [--watch-ms 1000]` (default watch on): calls same `board::projection()` as CLI, renders `ratatui` table/list, polls indexer (no git), `q`/Esc quits.
- Non-interactive fallback: `bb tui --once` prints same text as `bb board` (used in CI snapshot test).
- Manual proof: screenshot/typed check in e2e (CI runs `--once`; human runs interactive).
- Deps: `ratatui 0.29 + crossterm 0.28`; keep TUI code <200 lines, no business logic duplication.

### #1/sync — Deterministic issue sync (gh create-or-update only, no code commits)
- Input: `problems/001-blackboard-cli.md`. Parse frontmatter `issue:` (`null`/empty = none, else `#n` or `n`).
- Title: first `# ...` heading; body: full markdown file.
- If none: `gh issue create --title ... --body-file <tmp> --json number -q .number` -> `n`. Update frontmatter `issue: <n>` in place. Assert `issue-opened` tuple `{id:#1, state:done?}` — use `type: issue-opened, state: done, refs:[md, gh://.../issues/n]`.
- If exists: `gh issue edit <n> --title ... --body-file <tmp>` (no comment spam in MVP).
- Then ensure 5x `slice-state open` tuples (actor `sync`, summary `waiting pick`) for `#1/{core,cli,board,tui,sync}` if not already present (idempotent: skip ids already in indexer).
- `sync` NEVER runs `git add/commit/push` (grep-enforced). `--offline` mode: skip `gh`, use fake `n=1` for tests.
- Tests: frontmatter parse null->1->edit; idempotent re-sync adds 0 tuples; no git invocation.

## 2. Test plan
- `cargo test`: unit (tuple validation, reduction, frontmatter parse, rebuild roundtrip).
- Genuine e2e `tests/e2e_two_agents.sh`: temp repo, `bb init`, `bb sync --offline`, `agent-1: pick core -> state executing -> done`, `agent-2: pick cli -> done` concurrently (background `&` + wait), then `bb board` asserts `[x] core`, `[x] cli`, `bb show #1` line count <=40, `rg git src/` empty check.
- TUI: `bb tui --once | diff <(bb board)` identical projection.
- Manual: `bb tui` watch + `cargo build --release` single binary smoke.
