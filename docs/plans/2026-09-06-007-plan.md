### 0.1 Why a real `Command::Help` instead of leaning on clap's `--help`

clap's auto-generated `--help`/`-h` (and its implicit `help` subcommand)
render *before* any of our code runs — there is no hook to inject the
resolved namespace or an install self-check into that output without
fighting clap's renderer. So: `--help`/`-h` stay exactly as clap generates
them today (script-safe, unchanged — nothing currently depends on `bb
--help`'s wording, but external tooling might, so it must not move).
`bb help` becomes a first-class subcommand we render ourselves, and bare
`bb` (no subcommand at all) routes to the same renderer — both need
`cmd: Option<Command>` in `Cli` (clap makes a subcommand-holding field
optional automatically when the type is `Option<_>`, no extra attribute
needed) and `disable_help_subcommand()` on the derived `Command` so our
`Help` variant isn't shadowed by clap's built-in one.

### 0.2 Namespace resolution (`src/namespace.rs`)

```rust
pub enum Origin { Explicit, Git(PathBuf), Default }
pub struct Namespace { pub root: PathBuf, pub origin: Origin }

pub fn resolve(explicit: &Option<String>) -> Result<Namespace> {
    if let Some(r) = explicit {
        return Ok(Namespace { root: PathBuf::from(r), origin: Origin::Explicit });
    }
    let cwd = std::env::current_dir()?.canonicalize()?;
    if let Some(root) = find_git_root(&cwd) {
        return Ok(Namespace { root: root.clone(), origin: Origin::Git(root) });
    }
    Ok(Namespace { root: default_root()?, origin: Origin::Default })
}

fn find_git_root(start: &Path) -> Option<PathBuf> {
    let mut dir = start.to_path_buf();
    loop {
        if dir.join(".git").exists() { return Some(dir); } // dir (repo) or file (worktree/submodule)
        if !dir.pop() { return None; }
    }
}

fn default_root() -> Result<PathBuf> {
    let base = std::env::var("XDG_DATA_HOME")
        .map(PathBuf::from)
        .unwrap_or(PathBuf::from(std::env::var("HOME").context("HOME unset")?).join(".local/share"));
    Ok(base.join("blackboard").join("default"))
}
```

`on_path(exe: &Path) -> bool`: scan `$PATH` entries for a `bb` (or
`bb.exe`, harmless even though Windows is out of scope) whose
canonicalized path equals `exe`'s canonicalized path. Used only by
`help::render_help` for the "on PATH: yes/no" line — read-only, no
subprocess, consistent with the crate's existing no-shelling-out
discipline (`grep -rn '"git"' src/` stays empty; this doesn't add any
`Command::new` calls either).

**Discovery vs. `--repo` never overlap.** `Origin::Explicit` short-circuits
before any filesystem walk — every existing e2e script always passes
`--repo`, so their behavior is byte-identical before/after #7. This is the
one regression risk in the whole plan and it's structurally prevented
(the `if let Some(r) = explicit` branch returns immediately).

## 1. Slice breakdown (instances of #7's current list, not a fixed schema)

### #7/namespace — `.git` walk-up + default fallback
- `src/namespace.rs` as in §0.2. `main.rs::repo_root()` deleted; every
  call site (`Cli.repo` reads) routes through `namespace::resolve(&cli.repo)?`
  once at the top of `main()`, same as today's single `repo_root()` call.
- `Store::new(&ns.root)` — the only call-site change; `Store` itself is
  untouched (confirms 0's "unchanged" claim).
- `explain()` in `main.rs` gains one line before/after the existing
  `explain: reads=... rows=... git=none` line: `namespace: <root> (<origin>)`
  where `<origin>` is `explicit --repo` | `git root` | `default (no git repo found)`.
- Unit tests (in `namespace.rs`, `#[cfg(test)]`, using `tempfile`-free
  manual tmp dirs like `store.rs`'s existing pattern): walk-up from a
  3-level-nested dir finds the right `.git`; a `.git` *file* (worktree
  style, content irrelevant — only presence is checked) is found the same
  as a `.git` dir; no `.git` anywhere under a scratch tmp root returns
  `None` (test must not accidentally walk into the real repo — build the
  tmp tree under `std::env::temp_dir()`, which is not inside this repo's
  git tree, and stop the walk at a synthetic boundary rather than the
  real `/`); `default_root()` respects `XDG_DATA_HOME` when set and falls
  back to `$HOME/.local/share` when unset (save/restore env var around
  the test — tests run single-threaded enough within this crate's
  existing `cargo test` setup, matching how `store.rs` tests already
  isolate via unique tmp dir names).

### #7/install — machine-wide install path
- `scripts/install.sh`: `#!/usr/bin/env bash`, `set -euo pipefail`,
  `cargo build --release --locked`, `install -Dm755 target/release/bb
  "${BB_INSTALL_DIR:-$HOME/.local/bin}/bb"`, then prints the final path and
  a one-line `PATH` check (reuse the same "scan `$PATH`" logic conceptually,
  but as a shell one-liner — this script has no dependency on
  `namespace.rs`, it's pure shell). Idempotent: safe to re-run after every
  `git pull`.
- `README.md` "Install" section rewritten (replaces today's "Build"
  section): primary path `cargo install --path .` (idiomatic, no root,
  lands in `~/.cargo/bin` which rustup already puts on `PATH`), documents
  `scripts/install.sh` as the fallback for non-cargo agents/environments,
  and a one-line namespace explainer ("`.blackboard/` lives at your
  nearest git root — run `bb help` to see which board you're on").
- No runtime code needed beyond `#7/help`'s self-check — installation
  itself is a build/release concern, not a code path.
- Test: `tests/e2e_namespace.sh` (shared with `#7/e2e`) shells out to
  `scripts/install.sh` with `BB_INSTALL_DIR` pointed at a tmp dir, then
  invokes that installed binary directly (not `$BB`) once to confirm it
  runs — smoke-level only, no assertion on real `~/.cargo/bin` or the
  developer's actual `PATH`.

### #7/help — rich `bb help` + bare `bb`
- `src/cli.rs`: `cmd: Option<Command>`; add `Help` variant (doc comment:
  "Full usage guide: workflow, verbs, and your current namespace."); call
  `.disable_help_subcommand()` via a `#[command(...)]` derive attribute (or
  a small builder post-processing step — clap v4 derive supports
  `#[command(disable_help_subcommand = true)]` on the top-level `Cli`
  struct) so `bb help` hits our variant, not clap's.
- `src/help.rs::render_help(ns: &Namespace, store: &Store) -> Vec<String>`:
  static block (condensed from `README.md`'s Human loop / Agent loop
  sections — kept in sync by hand, same discipline as `--about` text
  already is) + dynamic block:
  - `Namespace: <basename or "(default)"> (<root>)`
  - `  found via: <origin description>` (subdir-vs-root phrasing when
    `Origin::Git` and `cwd != root`, else "you are at the repo root")
  - `  state: .blackboard/ (log.jsonl + index.db)`
  - `Install: <current_exe path> (on PATH: yes|no)`
- `main.rs`: `None | Some(Command::Help) => { for line in
  help::render_help(&ns, &store) { println!("{line}"); } }` — this arm
  runs *before* `Store::init()` is required (help must work even if
  `.blackboard/` doesn't exist yet — `Store::row_count()`/`all_current()`
  already tolerate a missing `index.db` per `store.rs`'s existing
  `if !self.db_path().exists() { return Ok(vec![]) }` guards, so no new
  guard needed there).
- `bb --help` / `-h` / `bb <verb> --help`: **zero changes** — this slice
  touches only the `Help` variant's own rendering path and the bare-`bb`
  fallback; it does not touch `#[command(about/long_about)]` text used by
  clap's own `--help` (kept as today's short doc comments, maybe a
  one-line `after_help` pointer added: `"Run 'bb help' for the full guide."`
  — genuinely optional, low-risk if included).
- Tests: golden-string assertions (like `board.rs`'s existing render
  tests) for both the git-root case and the default-namespace case,
  driving `render_help` directly with constructed `Namespace` values
  (no process spawn needed for unit coverage; e2e covers the real CLI
  path).

### #7/e2e — subdir discovery, no-git fallback, `--repo` parity
- New `tests/e2e_namespace.sh`, same shape as `e2e_tabs.sh`:
  1. **Subdir discovery**: `mktemp -d`, `git init -q`, `mkdir -p a/b/c`,
     `cd a/b/c`, run `bb init` with **no** `--repo` — assert
     `.blackboard/` was created at the tmp repo root, not under `a/b/c`;
     run `bb help` from `a/b/c` and assert its `Namespace:` line names the
     repo root path.
  2. **No-git fallback**: fresh `mktemp -d` with `XDG_DATA_HOME` exported
     to a second tmp dir (never touches the real machine default), no
     `git init` — run `bb help`, assert it reports the default namespace
     under that `XDG_DATA_HOME`, and that `.blackboard/` lands there after
     `bb init`.
  3. **`--repo` still wins**: from inside the subdir-discovery repo,
     `bb --repo "$OTHER_TMP" board --explain` — assert the explain line
     names `$OTHER_TMP`, not the discovered git root (proves `Origin::Explicit`
     short-circuits).
  4. **Regression**: `cargo test`, `e2e_two_agents.sh`, `e2e_tabs.sh`,
     `e2e_dispatch.sh` all still green unmodified (they always pass
     `--repo`, so this is a pure regression check, not a new assertion);
     `rg '"git"' src/` still empty (namespace discovery is `Path::exists`,
     never a subprocess).
