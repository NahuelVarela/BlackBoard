## 1. Slice breakdown

### #2/filter — Open/Closed partition in shared projection
- `src/board.rs`: `pub enum Tab { Open, Closed }`, `pub fn is_open_state(s:&str)->bool` (`open|planning|executing|blocked` → open, `done` → closed).
- `pub fn partition_open_closed(p: &ProblemView) -> (Vec<SliceView>, Vec<SliceView>)` preserving slice order.
- `pub fn render_board_filtered(store, Option<Tab>) -> Vec<String>`: `None` = byte-identical #1 output (legend + full `ProblemView::render`); `Some` = same per-problem blocks but with filtered slice lists; empty slice list renders `(empty — everything is done)` (Open tab) or `(empty — nothing closed yet)` (Closed tab) inside the problem block.
- Empty board (no problems) unchanged: `(empty board — run bb sync <file> first)`.
- Tests: blocked∈open, done∈closed, order preserved, empty-state strings exact.

### #2/tabs — Tab bar UI + keybindings + counts (ratatui)
- `src/tui.rs`: `Tabs` widget with titles `Open (n) | Closed (m)` where n/m are global slice counts across all problems (same partition over `projection()`).
- Selected tab in event-loop local `usize` (0=Open default, 1=Closed). Keys: `Tab` toggles, `1`/`2` select, `←`/`→` switch, `q`/`Esc` quit. All other keys ignored.
- Watch mode keeps polling indexer each tick (reuse `store.row_count()` trick); counts recomputed per frame so live updates show.
- `run_once(store, Option<Tab>)` shares the filtered render with CLI (parity requirement). Keep TUI < ~150 lines new code, no business-logic duplication — all filtering via `board::` helpers.
- Manual proof: `bb tui` on #1's real board (all `[x]` done) shows `[Open (0)] Closed (5)` + empty-state; `Tab` switches.

### #2/cli — CLI parity (`board --open/--closed`, `tui --once --tab`)
- `Board`: `--open` / `--closed` bool flags, `conflicts_with` each other. Default (neither) = full board byte-identical to #1.
- `Tui`: `--tab <open|closed>` optional; only meaningful with `--once` (interactive ignores or starts on that tab? decided: interactive starts on requested tab, default Open). `--once` without `--tab` = full board (current behavior preserved).
- `render_board_filtered` + `run_once_tab` guarantee `bb board --open` output equals `bb tui --once --tab open` content (modulo outer chrome? decided: identical lines — TUI `--once` prints exactly the filtered board text, no chrome).
- Tests: CLI flag conflict, parity assertions in e2e via `diff`.
